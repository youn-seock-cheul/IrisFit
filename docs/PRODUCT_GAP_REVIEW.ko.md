# 원래 구상과 현재 앱의 차이·개발 우선순위

검토일: 2026-11-01. Walkthrough의 구상과 현재 소스/빌드 구성을 대조했다. 이번 작업은 정리·제안이며 기능 구현이나 제품/판매 방향 확정이 아니다. 신규 시장 조사·효능 검증·장시간 기기 시험은 수행하지 않았다.

## 후속 구현 갱신

30초 안내 세션과 사용자 확인 완료 기록을 실제 production 소스에 추가했다. 단위 18개·debug 실기기 UI 4개·전체 R8 release 외부 UI 1개 통과. [최신 구현·검증](GUIDED_SESSION_IMPLEMENTATION_2026-11-01.md). 60초 옵션·카메라/오버레이 운동은 구현하지 않았다. 아래 대조표는 구현 전 상태의 기록이며 최신 상태는 [세션 구현 기록](GUIDED_SESSION_DRAFT.ko.md)과 Walkthrough를 따른다. 고정 5분 제한 대신, 오래 걸리는 검증이 필요하면 예상 시간·목적·미실행 시 한계를 먼저 알려 사용자가 진행 여부를 판단하게 한다. 기본은 관련 단위 검사와 짧은 화면 확인이며 장시간 자연 알림·절전 시험은 자동 시작하지 않는다.

## 먼저 확인한 결론 — 최초 대조 시점

현재 release는 원래의 눈 운동·오버레이 앱이 아니라 **사용자가 시작하는 약 20분 뒤 1회 휴식 알림과 화면 타이머**다. 이전 P0 작업은 출시 위험을 줄였지만 제품의 핵심 체험까지 상당히 축소했다. 타이머의 동작 검증이 원래 구상의 완성을 뜻하지 않는다.

가장 먼저 보완할 후보는 **사용자가 짧은 안내를 따라 하고 완료할 수 있는 세션 경험**이다. 알림은 세션을 떠올리게 하는 보조 기능으로 둘 수 있다. 이 제안은 제품 결정을 대신하지 않으며 현재 앱을 자동으로 변경하지 않는다.

## 사용자에게 줄 가치 — 사실과 가설

- **지금 제공하는 가치:** 계정·카메라 없이 타이머 시작/취소, 화면 내 남은 시간, 약 20분 뒤 한 번 알림, 로컬 기록 삭제. ‘휴식 기록 삭제’ 버튼이 있다고 완료 기록 기능이 있는 것은 아니다.
- **먼저 구체화할 가치 가설:** “화면을 오래 본 뒤 무엇을 하면 좋을지 몰라도 짧은 안내를 따라 휴식을 마칠 수 있다.” 시작 → 안내 → 중지/완료 → 실제 완료 기록의 흐름이 필요하다. 사용자에게 유용한지는 이후 짧은 체험으로 확인한다.
- **후속 차별화 가설:** 선택형 오버레이 안내 또는 카메라 피드백. 다른 앱을 가리는 불편과 카메라 부담을 상쇄할 이점이 있을 때만 추가한다. 정확한 시선/피로도·치료 효과는 현재 코드에서 제공하지 않는다.
- 가격·판매 방식·대상 사용자 확정은 보류한다. ‘타이머만 판매’ 또는 ‘카메라 반드시 도입’을 확정하지 않는다.

## 빠진 핵심 기능과 권장 순서

| 순서 | 다음 산출물 | 완료 기준·범위 |
| --- | --- | --- |
| 1 — 다음 작업 | **30~60초 앱 내 안내 세션의 화면/흐름 초안** | 시작, 단계 안내, 일시정지/즉시 종료, 완료/다시 하기. 화면에서 눈을 떼는 휴식과 화면 속 마커를 따라보는 활동을 별도 루틴으로 표현. 우선 카메라 없이 체험 가능하게 제안 |
| 2 | 세션 상태·완료 기록 최소 설계 | 중도 종료를 완료로 집계하지 않음. 회전/화면 이탈 정책, 실제 완료 횟수·일자, 기록 삭제 정의. 건강 개선 점수로 환산하지 않음 |
| 3 | 원래 오버레이/카메라 구상의 작은 실험 범위 명세 | 앱 내 루틴에 비해 추가되는 이점, 필요한 입력/권한·수동 시작/즉시 종료, 감지 불가 표시 정의. 중앙 고정 좌표로 시선 성공 판정 금지 |
| 4 | 제품 화면·이름·스토어 초안 정합성 | 실제 제공 기능만 설명. 현재 '타이머' 초안은 임시 범위임을 유지하고, 최종 체험에 맞춰 갱신 |
| 출시 전 | 남은 기술/운영 P0 | 공개 개인정보처리방침·지원 정보·서명/Console 등은 계속 필요. 미완료 장시간 시험은 삭제하거나 통과로 바꾸지 않고 보류 상태로 유지 |

‘눈 운동 앱이 원래 구상이므로 모든 과거 기능을 즉시 복원’하는 순서도 권하지 않는다. 사용자 체험을 작은 범위로 만들고, 검증되지 않은 시선·능력 수치를 연결하지 않는 것이 우선이다. 이번 정리에서는 앱 코드와 권한을 변경하지 않았다.

## 짧은 검증 원칙 — 사용자 요청 반영

- 장시간 자연 알림·재부팅·절전·배터리 관찰은 자동으로 시작하지 않는다. 이번 장시간 시험도 중단 상태를 유지한다.
- 이후 기본 검증은 관련 정적 분석, 기존 단위 테스트, 짧은 화면 조작으로 한정한다. 고정 5분 제한 대신, 오래 걸리는 검증이 필요하면 예상 시간·목적·미실행 시 한계를 먼저 알려 사용자가 진행 여부를 판단하게 한다. 기본은 관련 단위 검사와 짧은 화면 확인이며 장시간 자연 알림·절전 시험은 자동 시작하지 않는다.
- 실제 시간 경과가 필요한 신뢰성 검증은 별도 장기 항목으로 남긴다. 짧은 시험/시간 주입 결과를 자연 시간 경과 통과로 표시하지 않는다.
- 문서만 수정한 이번 작업에서는 빌드·실기기 테스트를 새로 실행하지 않았다. 기존 UI 3개/단위 8개 통과는 이전 실행 증거다.
