# 안내 종료 신호 옵션 설계

상태: 옵션·종료 신호 구현 완료, release 빌드/경계 검사·단위 18개·debug 실기기 UI 2개 통과. UI의 테스트용 수신기로 미리 확인·종료 요청 1회·반복 tick 중복 방지를 확인했고 실제 소리/진동 체감은 미확인이다. 아래 ‘미완료: 앱 구현’ 등은 구현 전 설계 기록이며 최신 상태는 이 문단과 Walkthrough를 따른다.

구현: EndSignalMode, EndSignalPlayer와 ViewModel/Activity 연결. 정상 tick의 Running→Confirm 전환에서만 즉시 요청하며 상태 재수집 이벤트 큐를 두지 않아 회전/복귀에 재생하지 않는다. onPause에서 연결 해제·신호 중지 후 시간 일시정지를 처리한다. 소리는 최대 약 600ms, 진동은 180ms 1회이며 기기 무음·방해 금지 제한을 우회하지 않는다. VIBRATE 일반 권한을 추가했다. [공식 진동 속성 API](https://developer.android.com/reference/android/os/VibrationAttributes)를 참고했다. 실제 체감은 별도 확인이 필요하다.

아래는 구현 기준으로 유지한 설계 기록이다. 기존 20분 알림과 별개로, 사용자가 앱을 열고 실행한 30초 안내의 종료를 알아차리도록 돕는 옵션이다.

## 화면과 선택

준비 화면에 ‘종료 알림 방식’ 선택 영역을 둔다.

| 옵션 | 동작 |
| --- | --- |
| 무음 (기본) | 종료 화면만 표시 |
| 짧은 소리 | 안내 종료 시 짧은 신호 1회 |
| 짧은 진동 | 지원 기기에서 짧은 진동 1회 |
| 소리와 진동 | 두 신호 각 1회 |

선택만으로 신호를 재생하지 않는다. 별도의 ‘선택한 신호 미리 듣기/확인’ 버튼을 사용자가 눌렀을 때만 짧게 체험한다. 무음이면 미리 확인 버튼은 표시하지 않는다.

설명: ‘기기의 음량·무음·방해 금지 설정에 따라 신호가 들리거나 느껴지지 않을 수 있습니다. 기기 설정은 바꾸지 않습니다.’

최초 구현은 세션마다 준비 화면에서 선택하고 앱 재실행 시 무음으로 돌아가는 방식이다. 선택을 영구 보관하거나 완료 기록의 새 필드로 저장하지 않는다. 사용자 설정 보관은 이후 필요성을 확인한다. 실행 중 옵션은 고정하며 다음 안내는 다시 준비 화면에서 선택한다.

## 발생·중복 방지 기준

- Running에서 실제 안내 시간이 끝나 Confirm으로 바뀔 때만 한 번 요청한다. 완료 기록 저장 성공 시점에 울리는 것이 아니다.
- 일시정지·중도 종료·뒤로 가기·삭제·기록 저장/재시도에는 신호 없음.
- 회전·재구성·완료 화면 재진입·앱 복귀·프로세스 재시작으로 재생하지 않는다.
- 앱이 비활성화되거나 화면이 잠기면 기존 정책대로 일시정지한다. 이탈을 처리하는 경로에서 마침 시간이 다 지났더라도 신호는 억제한다. 나중에 앱으로 돌아와도 지연 신호를 재생하지 않는다.
- 신호 실패/진동 미지원이어도 Confirm 화면과 사용자 확인·기록 저장 기능은 정상 제공한다. 신호 성공을 실제 휴식 완료로 간주하지 않는다.

## 구현 경계

ViewModel의 세션 ID별 일회성 종료 이벤트와 Activity의 신호 재생기를 분리한다. 상태가 Confirm이라는 이유만으로 Compose LaunchedEffect에서 매번 재생하지 않는다. 이벤트는 소비 처리한 뒤 현재 화면 활성 여부를 확인해 재생하며 비활성 이벤트는 폐기한다. 프로세스 종료를 넘어 종료 이벤트를 보관하지 않는다.

소리는 알람용 스트림이나 강제 볼륨 조절 없이 짧은 안내 음원과 적절한 AudioAttributes를 사용한다. 진동은 하드웨어 지원을 확인하고 Android의 VIBRATE 일반 권한이 필요하다. 최종 API/오디오 정책은 구현 시 공식 문서와 기기 동작을 대조한다. 정확한 알람·백그라운드 서비스·방해 금지 우회 권한은 이 기능의 요구사항이 아니다.

기존 release 경계 검사에 권한 목록이 있으므로 VIBRATE 추가 시 의도한 변경을 검토한다. 개인정보 안내·상품 설명의 ‘무음’ 표현도 ‘기본 무음, 선택형 신호’로 함께 수정한다.

## 짧은 검증 계획

- 단위: 가짜 시계와 가짜 신호 수신기로 종료 1회, 중단/이탈 0회, 중복 tick·재구성·저장 재시도 0회 추가 요청을 확인. 실제 대기 없음.
- UI: 준비 화면 옵션·초기 무음·미리 확인의 명시적 조작 확인.
- 기기: 선택한 모드로 실제 30초 안내 1회, 종료 화면/기록 확인과 신호 발생 관찰. 이후 중도 종료 시 신호 없음 확인. 약 1~2분 예상.
- 소리·진동의 실제 체감은 사람의 확인이 필요하다. 자동 이벤트 횟수 검사를 ‘들렸다/느껴졌다’는 결과로 기록하지 않는다. 개인 기기 음량을 임의로 바꾸지 않는다.
- 오래 걸리는 제조사·절전 검증이 필요하면 예상 시간·목적·한계를 먼저 알려 사용자가 판단하게 한다.

## 완료·남은 작업

완료: 옵션·기본값·발생 시점·일회성 처리·이탈 억제·미리 확인·실패 처리·검증 기준.
미완료: 앱 구현·권한/오디오 API 적용·실기기 소리/진동 확인.
다음 우선순위: 이 설계대로 준비 화면 옵션과 일회성 종료 신호를 구현하고 짧게 검증.
지금 필수 사용자 결정 없음. 기본 무음을 유지하는 변경 가능한 설계안이다.
