# 마커 설정 기억·불러오기

사용자가 속도2/5(왕복14.5초)·범위60%가 ‘딱 좋다’고 확인했다. 이는 해당 사용자의 선호이며 전체 사용자 기본값이나 건강 효과 근거로 확대하지 않는다.

## 최종 실행 결과

단위28개·debug UI2개(28.367초)·release 빌드/Lint/설치 성공. UI 검사는 새 ViewModel 복원과 삭제를 확인했고, 별도로 최종 release에서 ‘이 설정 기억’을 직접 눌러 사용자 선호2/5·60% 저장 성공→프로세스 강제 종료→앱 재실행→마커 준비 화면에서 동일 조합/왕복14.5초 복원을 확인했다. 기본값은 변경하지 않았다. 사용자 선호는 이 기기에만 저장됐다.

## 구현

- 준비 화면의 ‘이 설정 기억’을 눌렀을 때만 현재 속도·범위를 앱 전용 marker_preferences_v1.txt에 저장한다.
- 초기화로 현재 슬라이더를 바꿔도 저장된 설정은 유지하고 ‘저장한 설정 불러오기’로 복원한다. 현재 값과 기억한 값을 따로 표시한다.
- 새 프로세스의 ViewModel을 초기화할 때 저장한 설정을 적용한다. 기존 프로세스에서 앱 복귀/회전만으로 편집 중 슬라이더를 덮어쓰지 않는다.
- 저장 실패는 성공 표시 없이 다시 저장할 수 있다. 저장 중 슬라이더와 시작 버튼을 잠시 비활성화한다.
- ‘이 기기의 앱 기록 전체 삭제’는 저장한 마커 설정도 삭제하고 기본값으로 되돌린다.
- 두 단계 인덱스만 한 번에 AtomicFile로 저장하며 IO 작업은 메인 스레드 밖에서 실행한다. 다른 ViewModel의 저장과 겹치지 않게 직렬화한다.
- 파일은 기존 백업/기기 이전 제외 규칙의 대상이다. 서버 전송·새 권한은 없다. 개인정보 안내와 공개 방침 초안에 추가했다.
- 저장한 설정이 없으면 기존 기본값(속도5/5·범위100%)을 사용한다. 사용자 선호를 앱 공통 기본값으로 하드코딩하지 않는다.

## 검증

단위28개 통과(새 설정 검사4개 포함): 명시적 저장과 새 저장소에서 읽기, 저장 실패 시 기존값 보존, 삭제 후 빈 상태, 잘못된 단계 거부.

실기기 검사는 저장 전 파일 없음, 저장 후 파일 값, 초기화 후 명시적 복원, 새 ViewModel 초기값 복원, 전체 삭제를 확인한다. 새 ViewModel 검증은 실제 프로세스 재시작과 구분한다. 최종 결과 및 실제 재실행 확인은 Walkthrough 최신 항목에 기록한다.

## 다음 순서

선호 설정을 기억한 뒤 실제 앱을 종료·다시 실행해 동일 조합이 복원되는지 짧게 확인한다. 이후에는 새 옵션 확장보다 기존 두 루틴의 정합성·출시 준비 검토를 우선한다. 장시간 시험은 예상 시간/목적을 먼저 안내하고 사용자 판단을 받는다.
